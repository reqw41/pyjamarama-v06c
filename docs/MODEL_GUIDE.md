# Модель логики Pyjamarama V1: как писать и проверять подпрограммы

Цель: JS-модель логики, байт-в-байт эквивалентная ZX (редакция V1). Память модели — образ ZX (адреса оригинала).
Рисование не моделируется пикселями: каждый вызов «листового» рисующего примитива пишется в журнал `c.log`, а его эффект на
логику (атрибуты 0x5800.., регистры) делает `prim(c,'ИМЯ')`. Журнал и память модели сверяются с ZX (tools/difftest.js).

## Файлы
- `ref/pyjamarama.lst` — дизассемблирование (SkoolKit), `build/code.txt` — то же, без длинных блоков DEFB;
  `python3 tools/show.py ADDR_FROM ADDR_TO [ширина]` печатает код по адресам (hex).
- `tools/sym.js` — `SYM[метка]=адрес` из листинга (все метки V1).
- `src/model/core.js` — `Ctx`, `prim`, `PRIM` (примитивы рисования), `S`=SYM. **Образцы стиля:** `src/model/wally.js`, `src/model/room.js`.
- `tools/zxgame.js` (эталон на ZX-модели; `g.enterRoom(n,x,y)` телепорт, `g.call(addr,regs)`), `tools/difftest.js`, `tools/run_diff.js`.
- `build/v1/ram.bin` — память V1 после распаковки (стартовое состояние стенда).

## Контракт подпрограммы модели
`fn(c)` где `c.M` — память (Uint8Array 64К), `c.r` — регистры `{a,b,c,d,e,h,l,ix,iy}` (+ `c.hl/de/bc` парные геттеры/сеттеры),
`c.b(a)/c.sb(a,v)/c.w(a)/c.sw(a,v)` — байт/слово (little-endian). Подпрограмма меняет `c.M` и `c.r` так же, как ZX-код
(в т.ч. регистры, которые вызывающий использует после возврата!). Вызов другой подпрограммы модели — обычный вызов JS-функции
с тем же `c`. Регистрация для сверки: в экспорте `R = { ИмяМетки: { fn:(M,r,i)=>..., out:['hl','a',...], rand:[адреса] } }`
(см. `run()` в room.js). `out` — регистры, которые сверяются после возврата.

## Примитивы рисования (PRIM в core.js)
Листовые рисующие подпрограммы не переписываются, а вызываются как `prim(c,'Bitmap16Draw')` (A=индекс; X,Y в BitmapX/BitmapY),
`'TileDraw'`, `'Tile_DrawFlip'`, `'Tile_BlitDoubleHeight'`, `'Beep_Effect'` (BC,DE,HL — звук), `'Milk_DrawFull'`, `'ScreenClear'`.
Если вашей подпрограмме нужен новый листовой примитив (рисует только пиксели, не читает их), добавьте его **из своего модуля**:
`PRIM.Имя={ zx:(M,st)=>['имя',...аргументы], fx:(c)=>{c.log.push([...]); /*эффект на атрибуты/регистры*/} }` — `zx` строит запись
журнала из состояния ZX на входе в подпрограмму `SYM[Имя]`, `fx` — то же из модели; записи должны совпасть. Если подпрограмма
из вашего набора читает пиксели экрана 0x4000..0x57FF — сообщите в отчёте (это отдельное решение).
Пиксельная область 0x4000..0x57FF при сверке памяти не сравнивается; **атрибуты 0x5800..0x5AFF сравниваются**.
Самомодифицирующийся код: если подпрограмма пишет в свой код/операнды (адреса вида 0xAB26), это состояние памяти — моделируйте
(кроме двух байт в Bitmap16Draw 0xAB26/0xAB32 — они уже игнорируются).

## ЛД А,R и прочее недетерминированное
`LD A,R`: укажите в `R[имя].rand=[адрес команды, следующей за LD A,R+... ] ` — стенд кладёт значение A на входе этой команды в
`inputs.rands` (очередь, `c.inputs.rands.shift()`), как в `Wally_TurnHead` (ADA5 — адрес команды после `LD A,R`). Клавиатура: `c.inKey(порт)`.

## Проверка
`node tools/run_diff.js ТИКОВ SEED МОДУЛИ [КОМНАТЫ]` — стенд играет случайными клавишами (O, P, M), на каждом входе в подпрограммы
из реестра снимает состояние ZX, после возврата прогоняет модель на копии и сверяет память (0x5800..0xFFFF кроме стека),
регистры `out` и журнал примитивов. Пример: `node tools/run_diff.js 900 4 wally,room,events_a 2,3,9,15` — модули из src/model/,
комнаты — телепорт по очереди (равными долями тиков). **Покрытие:** убедитесь, что каждая подпрограмма вызвалась (счётчик «вызовов»)
и во всех ветвях (используйте разные комнаты и seed, при необходимости `g.enterRoom`, запись в память стенда для редких условий:
в скрипте-обёртке меняйте `g.mem[...]` между тиками). Целевой результат: 0 расхождений на ≥3 seed и всех комнатах, где подпрограмма живёт.
Отказ `Error: ... не реализован` из Room_TestEvents/Action — зона ответственности другого модуля, не ваша.
Не правьте чужие модули (wally.js, room.js, core.js, difftest.js) — если нужно, опишите проблему в отчёте. Добавлять в `tools/` свои скрипты можно.
