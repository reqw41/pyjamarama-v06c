# План порта на Вектор-06Ц (решение владельца 1.11.2026)

**Нативный i8080 по JS-модели, а не рекомпиляция логики.** Модель (src/model, сверена с ZX на 9000 тиков) — источник правды; по ней пишем
оптимизированный код i8080 (как в jetpac-v06c: модель → i8080, сверка по шагам). Сначала игра работает на Векторе (монохромно, одна плоскость),
раскраска (8 цветов, docs/COLOR.md) — потом.

## Роль механического переводчика (tools/z80to8080.py + tools/vendor/z80_to_8080.py)
Остаётся инструментом, не продуктом: (1) оценка размера/скорости (весь код ZX → i8080: 11 КБ, собирается `sjasmplus --i8080` без ошибок);
(2) запасной путь для редко исполняемого «фронта» (заставка, меню, настройка клавиш, титры, демо), пока нативная версия не готова;
(3) независимый оракул для стенда. Нативный код с ним не смешиваем без нужды.

## Раскладка памяти (набросок, уточнить замером)
- Данные игры: 24,5 КБ (спрайты 6,4, тайлы 4,4, мебель 3,8, комнаты 0,8+скрипты 1, салют 1,3, текст, музыка/демо; таблица DF 0,4 не нужна, титульный буфер 5,5 не нужен).
  Едут одним сдвигом **−0x8000**: адрес ZX 0x8200..0xFC9F → 0x0200..0x7C9F, поэтому модель и стенды работают на тех же смещениях (`M[addr-0x8000]`).
- Код: нативный i8080 ~8–10 КБ (механический перевод — 11 КБ как верхняя оценка); в дырах между блоками данных и в плоскости 3 (0xE000–0xFFFF, невидима при палитре,
  игнорирующей бит 3 — рецепт KL §17).
- Экран: плоскость 0 (0x8000–0x9FFF, 256×256, столбцами) на первом этапе; строки вне картинки (192 из 256 видимых) — «дыры» под данные (KL §17.5).
  Карта атрибутов ZX (768 Б) — служебная, логика читает её для столкновений (пол 0x42/0x45) и фона под Wally.
- Стек, ячейки, ВИ53-очередь — по рецепту KL §2/§3.

## Этапы
0. Стенд (готов): ZX-эталон (tools/zxgame.js), модель, сверка по тику (tools/run_tick.js).
1. **Скелет на Векторе:** загрузка, ISR (палитра в VBlank, скан клавиатуры → ряды ZX, джойстик «П»), очередь звука на ВИ53 — по склейке Knight Lore
   (docs/REUSE.md); карта данных со сдвигом; генератор образа данных tools/mkvecdata.py (из build/v1/ram.bin и разметки).
2. **Нативный шаг игры** по модулям модели, каждый — со сверкой по тику с ZX (состояние через таблицу переменных ZX→Вектор, журнал примитивов):
   Wally (ввод, ход, прыжок, падение) → комната (скрипты, инвентарь, отрисовка) → события комнат → захватчики/аркада → смерть/воскрешение.
   Алгоритмы оптимизируем там, где модель позволяет (таблицы вместо вычислений, Wally без перерисовки XOR двух пар, и т.п.), поведение — как у ZX.
3. **Примитивы вывода** на плоскости: Bitmap16Draw (XOR 16×16 со сдвигом, столбцовая раскладка, таблицы сдвига), TileDraw/Flip/Double, молоко, очистки,
   ракета, магнитные прутья, движущийся пол; сверка с журналом модели и по картинке (снимки vector06js).
4. Фронт: заставка (6,9 КБ экран ZX — пережать), меню, клавиши, титры, победа/салют, музыка и эффекты на ВИ53, демо (по месту).
5. Образы `.r0m/.c00/-0100.rom`, README по шаблону портов, гейты (check_i8080, hangwatch, inputcheck), выкладка в публичный репозиторий.
6. Потом: раскраска (docs/COLOR.md), 3 плоскости без клэша.
