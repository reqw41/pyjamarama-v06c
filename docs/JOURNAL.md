# Pyjamarama → Вектор-06Ц: журнал

## 2026-11-01 разведка
Решения владельца: механика оригинала, 8 цветов (раскраска по itch.io minionsoft), ванильный Вектор 64 КБ, звук на ВИ53.

Что есть:
- `src_orig/*.tap` — Pyjama1 (BASIC), Pyjama2 (экран 6912 Б + 38 Б загрузчик), Pyjama3 (0x64FF..0xFFFF, 39680 Б). Код защищён: старт `USR 33040` (0x8110) расшифровывает себя за ~7000 инструкций. `tools/unpack.js [N]` гонит загрузчик на ZX-модели (tools/zx48.js, vendor/Z80.js, ref/48.rom — копии из jetpac-v06c) и пишет `build/ram.bin` (память с 0x4000). Рабочий снимок — N=16470 (до старта музыки заставки).
- `ref/pyjamarama.lst` — дизассемблирование luny.co.uk (SkoolKit 6.0, Wayback 2018-09-01), 234 блока, получено `tools/fetch_asm.sh` + `tools/html2asm.py`. `tools/lst2asm.py` + sjasmplus собирают его в `build/lst.bin`.
- **Дизассемблирование luny и TAP владельца — РАЗНЫЕ РЕДАКЦИИ.** Сравнение lst.bin ↔ ram.bin (difflib): 61 структурное отличие ≥4 байт. Код сдвинут на −10 (8C4D..A9BB) и −33 (BC9F..E172) относительно luny; в TAP нет демо-режима (1107 Б по 0xF81B) и другая таблица комнат/мелодия заставки; переставлены таблицы 8CAA..8D1B. Механика (комнаты, предметы, события) совпадает по подпрограммам. Поэтому: **ground truth = ram.bin из TAP**, luny-листинг = словарь имён и комментариев; метки переносить по сопоставлению байтовых образцов.

Объём игры: 0x64FF..0xFFFF = 39 КБ (из них 5,5 КБ копия заставки, ~3,7 КБ строки мебели, 4,4 КБ тайлы). Экран ZX 256×192.
Бюджет Вектора (оценка, не замер): 3 плоскости × 6 КБ (256×192) = 18 КБ видео, остаётся ~46 КБ под код i8080 (Z80→8080 раздувает ×1,3–1,6), данные, таблицы сдвигов.

Открыто:
1. Раскраска: itch-версия — платный PICO-8 ремейк без исходников; в архиве full-pyjamarama.zip лежат .p8/.p8.png картриджи (спрайты и карты читаются). Нужен архив от владельца либо скриншоты.
2. Модель: JS-модель логики → i8080 с lockstep против ZX (как в jetpac-v06c/tools/lock80.js).
3. Звук: пищалка ZX (порт FE) → ВИ53; заставка-мелодия F68D..F8xx, эффекты AFBE/AFD8/AFEB.

## 2026-11-01 (позже): три TZX от владельца

Структура у всех: BASIC (472 Б) -> код в области переменных (`USR VARS+28`) -> загрузчик 0x8016 -> экран 0x4000 (турбо) -> игра 0x8200..0xFC9F (31392 Б), `JP FC89`. `tools/tzxdump.py` режет TZX на блоки, `tools/unpack_tzx.js <tc|v1|v2>` подменяет ленту (0x804F) и проверку суммы (0x803F) и снимает память в build/<ред>/ram.bin.
**Результат сверки с luny (tools/cmp_edition.py): редакция luny = V1.** 31189 из 31383 байт равны позиционно, остальные 194 — строки DEFM (мой ассемблер их кодирует иначе) и 4 рабочих ячейки. Trade Copy и V2 между собой почти одинаковы (12784 байт равно), TAP (Pyjama3) — отдельная перепаковка без демо.
=> Основа порта: **V1** (build/v1/ram.bin, состояние на входе в заставочную музыку F68D) + листинг luny как есть, без сопоставления сдвигов. Отличия V2/TC/TAP от V1 (исправления ошибок?) — отдельная задача, смотреть после модели.

## 2026-11-01 (вечер): модель логики V1, этап 1
Подход: «логика + журнал примитивов рисования». Модель ведёт всю логику и атрибуты ZX на образе памяти ZX (адреса оригинала),
пиксели (0x4000..0x57FF) не ведёт: каждый вызов листового рисующего примитива (Bitmap16Draw, TileDraw, Tile_DrawFlip,
Tile_BlitDoubleHeight, Beep_Effect, Milk_DrawFull, ScreenClear, ScreenClearEffect) пишется в журнал и сверяется с журналом ZX.
Это же будущий поток команд для рисовалки Вектора. Руководство для исполнителей — docs/MODEL_GUIDE.md.

Стенд: tools/zxgame.js (V1 на ZX-модели со старта игры, g.tick(клавиши), g.enterRoom(n), g.call(addr)), tools/difftest.js

  (фон-атрибуты Wally_BgColour), HitTest, Energy_Countdown, Milk_DecreaseByAmount, Wally_EnergyIncBy (с квирком займа C→B в Bmp_DrawRows).
